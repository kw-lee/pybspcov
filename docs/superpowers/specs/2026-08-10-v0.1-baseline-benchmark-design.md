# v0.1 Baseline Benchmark Design

## Goal

Record a reproducible pre-release performance baseline for the public
`BMSPCov` and `SBMSPCov` estimator source at commit `69e3535`. Benchmark-only
commits may follow it, but this task does not modify `src/pybspcov`. The
baseline supports optimization decisions and will be rerun for the eventual
`v0.1.0` tag. It is not statistical convergence evidence.

## Scope

- Dimensions: 25, 50, 100, and 200, with `n = 3p`.
- Estimators: BM and correlation-screened SBM.
- Backends: CPU and NVIDIA GPU on the same host.
- Precision: float32 and float64.
- Workload: 5% target density, one burn-in sweep, two retained sweeps, three
  warmed repetitions, and seed 20260803.
- Measurements: first fit, warmed-fit median/minimum/maximum, public-output
  validity, truth-relative Frobenius error, and complete runtime provenance.
- Short chains are used to measure scaling without presenting posterior
  summaries as scientific results.

## Implementation

Generalize the existing `benchmarks/sbm_public_scaling.py` runner with an
`--estimator {bm,sbm}` option. Preserve its fixture generator, synchronization,
timing, validation, and JSONL schema. Estimator-specific fields may be null for
BM. Do not add another benchmark framework or notebook.

Add only focused tests for estimator selection and output schema. GitHub CI
continues to run smoke tests; it does not run the hardware benchmark matrix.

## Recorded outputs

Store one curated machine-readable JSONL result per estimator, backend, and
precision under `benchmarks/baselines/0.1.0.dev0/`. Store one concise Markdown
report beside them containing:

- the exact commit, host, software versions, and commands;
- tables for BM and SBM first-fit and warmed timings;
- GPU/CPU speed ratios and float32/float64 error comparisons;
- failures or unavailable cells without interpolation; and
- explicit limitations of short-chain and single-host measurements.

Raw exploratory runs remain untracked. The report makes no universal speedup
or scientific-equivalence claim.

## Acceptance criteria

1. Existing SBM CLI behavior remains available.
2. BM and SBM produce valid, synchronized JSONL records for all successful
   matrix cells.
3. The committed Markdown report is derivable from the accompanying records
   and answers when GPU or float32 helped on the measured host.
4. The relevant benchmark tests and repository quality hooks pass.
