# v0.1 Long-Chain Baseline Benchmark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the invalid short-chain baseline with ten long-chain, four-chain repetitions for every BM/SBM CPU/GPU precision cell and a repeated R comparison.

**Architecture:** A public-estimator runner records one compiled warm-up and ten measured repetitions. A subprocess orchestrator runs a NUMA-1 CPU/R lane concurrently with a NUMA-0 GPU lane, while a separate renderer validates raw records and creates the report and SVG boxplots.

**Tech Stack:** Python 3.12+, JAX 0.11, NumPy, pytest, R 4.x, bspcov 1.0.3, numactl, Matplotlib, JSONL, SVG, Markdown

## Global Constraints

- Do not modify `src/pybspcov`.
- Use `p = 25, 50, 100, 200`, `n = 3p`, density 0.05, and fixture seed 20260803.
- Use 50 burn-in sweeps, 50 retained samples, four chains, and ten measured repetitions in every Python cell.
- CPU uses one vmapped four-chain fit; GPU uses four sequential single-chain fits.
- Exclude one synchronized compile-plus-execution fit per cell from primary timings.
- Pin GPU work to NUMA node 0 and CPU/R work to NUMA node 1.
- Remove, rather than preserve, every curated burn-in-1/two-sample result.
- Use boxplots with all raw points; do not use violin density estimates for ten observations.
- Do not run the hardware matrix in GitHub CI.
